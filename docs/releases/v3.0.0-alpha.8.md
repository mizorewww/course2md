# v3.0.0-alpha.8：设置即生效，AI 校对更稳，嵌套列表滚动

3.0.0 的第八个预览版。处理选项只在「设置」里，改了立即对之后开始的工作生效；AI 校对改为分小段流式发送，失败的部分自动重试，也可以只重试没完成的部分；可滚动页面里的列表滚动时页面不再跟着动。请先在不重要的视频上试用，遇到问题请[反馈](https://github.com/mizorewww/course2md/issues)。

## 处理选项只在设置里（#67）

之前每个视频在主页都有自己的一份「处理选项」，提交后任务会带着当时的选项运行，于是在设置里换了模型，排队中、继续或重试的任务仍然用旧模型。这个功能已经整体移除：

- **设置是唯一的来源**：每次转换在开始工作时读取当时的设置，排队中、继续、重试和在主页重新生成的任务都一样。「设置 → 生成笔记」里注明了这一点。原来主页面板里的每个选项在设置中都有，没有功能丢失。
- **主页更简洁**：链接框下面是视频卡片（更换视频 / 开始转换），然后是「正在处理」和「最近的笔记」。视频卡片上的字幕标签只用来选择这个视频自己的字幕轨道、重新读取字幕或选择字幕文件；文字来源（自动 / 仅字幕 / 语音识别）只在设置里改。
- **继续之前改了设置**：只重做受影响的部分。例如换了语音模型，转写会按新模型重做，不会把旧转写和新设置混在一起。如果这会让已经付费完成的 AI 校对、翻译或摘要重新发送，继续前会先询问；内容没变的请求直接复用之前的结果，免费服务（本地 Ollama、Codex）不询问。
- **任务详情如实记录**：每段结果记录实际产生它的服务。只改了服务名称或密钥时，之前的结果直接复用，不会重新付费。
- **笔记命名和归档**：笔记使用视频名称，保存到默认笔记库；改名和移动到文件夹在笔记库中进行。
- 「调整后重试」等操作改为「在主页重新生成 / 在主页重试 / 在主页重新打开」。从暂停的任务回到主页时，卡片会说明开始转换将取代那个任务，也可以选择「继续原任务」。
- 旧版本保存的任务、草稿和设置都能正常读取，其中每个视频的选项会被忽略。

## AI 校对（#66）

之前每次校对请求可能输出到 16384 个 token 的上限，耗时 70 多秒：有时 JSON 在上限处被截断，报「服务返回的校对结构无效」，有时撞上 Ollama Cloud 约 75 秒的非流式网关超时（502）。现在：

- **请求更小**：每批最多 20 段、约 1500 字，输出上限按这一批的长度计算（通常约 4600 个 token）。使用 Ollama（包括地址为 ollama.com 的 OpenAI 兼容服务）校对和翻译时关闭思考。
- **流式发送**：所有 AI 请求（校对、翻译、摘要）都以流式接收，等待首个响应最多 300 秒，之后 90 秒没有新数据才算超时。
- **输出被截断时**保留已完整的段落，只重新请求缺少的部分；一段都没完成时，先用完整的输出上限再试一次，再对半拆分，每批最多 8 次请求。
- **自动重试**（默认开启）：超时、限流、服务器错误和无效回答最多重试 4 次，间隔 1、2、4 秒……最长 30 秒，遵守服务返回的 Retry-After；认证等错误不重试。可在配置 `[llm]` 的 `auto_retry`、`retry_attempts` 中调整。
- **只重试没完成的部分**：已完成的批次从已保存的结果读取，不再发送。部分失败时按钮显示「重试未完成的校对部分」/「重试未完成的翻译部分」。
- 服务拒绝某个参数（如 `stream_options`、思考设置）时，会去掉该参数再试一次。
- 注意：自动重试意味着付费服务中途丢失的回答会不经询问重新发送，可能多计费一次。

## 界面

- **嵌套列表单独滚动**（#68）：在可滚动页面里的列表（如服务编辑中的模型列表）上滚动，只有列表移动；列表滚到尽头时，这次滑动和惯性也不会带动页面。下一次滑动或移动指针后才会滚动页面。界面组件库更新到 gpui-kit-material 0.1.3。

## 验证范围

AI 校对的流式接收、截断恢复、重试和参数回退用本地模拟服务器逐项测试，尚未用真实的 Ollama Cloud、OpenAI 或 DeepSeek 账号验证。设置与任务的改动在 macOS 上用独立的测试数据实际运行并截图核对，包括继续前的费用询问；Windows 和 Linux 只经过自动测试和编译检查。嵌套滚动由组件库的引擎测试覆盖（div 和列表，开启与关闭滚动图层）；在 macOS 上实际运行确认了普通滚动和容器自身的滚动响应不受影响，但还没有在 course2md 的模型列表上实际操作验证。

## English

**course2md 3.0.0-alpha.8: settings take effect, steadier AI proofreading, nested lists scroll alone.**

**Options live in Settings only (#67).** Each video used to carry its own processing options from the home page, and a submitted task ran with that copy, so changing the model in Settings didn't reach queued, resumed or retried tasks.
- Every conversion now reads Settings when its work starts. No option was lost; all of them are in Settings.
- Home is the link field, the video card (Change video / Start), Processing and Recent notes. The card's subtitle chip only picks this video's own subtitle track or file; the text source is a setting.
- Resuming after a settings change redoes only what that change affects. If that would re-send paid AI work, it asks first; identical requests reuse their earlier answers, and free services (local Ollama, Codex) never ask.
- Task details name the service that actually produced each result.
- Older tasks, drafts and settings still open; per-video options in them are ignored.

**AI proofreading (#66).** Requests could run to the 16,384-token output cap for over 70 s, so the JSON was cut off ("invalid proofreading structure") or Ollama Cloud's ~75 s non-streaming gateway returned 502.
- Batches are at most 20 paragraphs or about 1,500 characters, with an output limit sized to the batch. Thinking is turned off for proofreading and translation on Ollama, including ollama.com set up as OpenAI-compatible.
- All AI requests stream: up to 300 s for the first response, then 90 s of silence ends it.
- A cut-off answer keeps its complete paragraphs and asks only for the rest; a batch that finished nothing gets one full-budget try and then two rounds of halves, at most 8 requests.
- Automatic retry is on by default: up to 4 attempts with 1, 2, 4 s… backoff (max 30 s), honouring Retry-After; auth errors aren't retried. `[llm] auto_retry` and `retry_attempts` adjust it.
- Retrying sends only what didn't finish; the button says so when part of the work failed.
- Note: with automatic retry, a paid request whose answer was lost is re-sent without asking and may be billed twice.

**Interface (#68).** Scrolling over a list inside a scrolling page, such as the model list in a service editor, moves only the list, and the rest of that swipe and its momentum stay with it at its end. The UI kit is gpui-kit-material 0.1.3.

**Install or upgrade:**

- `brew install mizorewww/tap/course2md-alpha` for the standalone CLI.
- Or use the downloads above; Windows has an installer.

Prereleases don't replace the stable release, and AUR skips them.

**Testing so far:**
- Proofreading streaming, truncation recovery, retries and fallbacks were tested against a local fake server, not yet against real Ollama Cloud, OpenAI or DeepSeek accounts.
- The settings and task changes were run and captured on macOS with isolated data, including the cost question before continuing. Windows and Linux are covered by automated tests and builds only.
- Nested scrolling is covered by the UI kit's engine tests (div and list, scroll layers on and off). Running on macOS confirmed ordinary scrolling and a container's own scroll handling are unaffected; the model list in course2md hasn't been tried by hand yet.

Please report any issues.

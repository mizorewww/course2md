# v2.0.0-rc.6：分 P 课程多选批量转换，下载进度与 token 实时可见

这是 **2.0 的第六个候选发布版（RC6）**。本版围绕「整门课一次整理」：分 P 视频列表显示真实分集标题与首帧预览，支持勾选任意多集一次批量转换；转换过程重新拥有看得见的进度——下载阶段的字节、速度与预计剩余，AI 阶段实时跳动的上传/下载 token。设置页修复了一个装饰性大圆圈，并把 Codex 订阅与 Ollama 本地服务以「AI 账号」卡片平级呈现。GitHub Latest、默认 Homebrew 包和 AUR 稳定包继续提供稳定版；试用 RC6 请使用本页附件或独立 RC 通道。

## 相比 RC5

- **分 P 列表显示真实标题与预览**：Bilibili 多集课程的候选列表不再只有「视频 n」，自动补全分集标题、首帧预览图与时长（每个 BV 一次公开接口请求，失败保留原候选不阻断）。
- **合集多选批量转换**：候选行改为勾选（鼠标整行可点，键盘 Tab+空格可切换），「整理选中的 N 个视频」一次把多集加入队列；支持全选/全不选。已有笔记的集带标记且不随全选重复转换，手动勾选时提示将生成新版本。批量任务不再要求逐集预先读取：任务运行时自行探测视频并发现字幕（Auto 模式与 CLI 语义一致，找不到字幕再回退语音识别），UP 主与时长自动补进笔记。
- **下载进度回归**：下载阶段显示已下字节、实测速度、预计剩余与确定性进度条，不再「转着圈却不知道在干什么」。
- **token 实时计数**：AI 校对与摘要阶段实时显示累计上传/下载 token（含 Codex 订阅的 usage 归一），长任务不再只有「等待服务返回结果」。
- **设置页**：修复侧栏装饰性大圆圈（共享选择轨道的发丝边在竖向轨道上被画成整圆）；「服务与账号」新增 AI 账号分组——Codex 订阅（导入/浏览器授权/退出）与 Ollama 本地服务（自动检测地址与模型、一键预填添加、已添加直达条目）平级可见。

## 下载桌面应用

GUI 包含同版本 CLI 引擎，无需另装 CLI。

| 平台 | 安装包 | 使用方式 |
| --- | --- | --- |
| macOS Apple Silicon，macOS 15+ | [DMG](https://github.com/mizorewww/course2md/releases/download/v2.0.0-rc.6/course2md-gui-macos-arm64.dmg) | 退出旧应用，将完整 `course2md.app` 放入「应用程序」 |
| Windows x64 | [桌面 ZIP](https://github.com/mizorewww/course2md/releases/download/v2.0.0-rc.6/course2md-desktop-windows-AMD64.zip) | 完整解压，打开 `course2md-desktop.exe`，保留同目录的引擎 |
| Linux x64 | [桌面 tar.gz](https://github.com/mizorewww/course2md/releases/download/v2.0.0-rc.6/course2md-desktop-linux-x86_64.tar.gz) | 完整解压，运行 `./course2md-desktop`；预编译包基于 Ubuntu 24.04 |

处理视频需要 ffmpeg/ffprobe，在线视频还需要 yt-dlp。Homebrew 会安装这些依赖；手动安装请参阅 [安装指南](https://github.com/mizorewww/course2md/wiki)。Intel Mac 和 Linux ARM64 提供独立 CLI，暂不提供预编译 GUI。

## Homebrew RC 通道

首次安装：

```sh
brew update
brew install --cask mizorewww/tap/course2md-gui@rc
```

已有稳定版或 alpha/旧 RC 的用户，先退出应用，再卸载原 cask（`course2md-gui`、`course2md-gui@alpha` 或旧 RC），然后安装 RC cask。卸载时不要加 `--zap`，以保留用户数据。手动安装过的应用可先移出「应用程序」留作备份。

后续更新使用 `brew upgrade --cask course2md-gui@rc`。独立 CLI 也有 RC 通道，默认不替换终端中的稳定版命令：

```sh
brew install mizorewww/tap/course2md-rc
"$(brew --prefix course2md-rc)/bin/course2md" --version
```

独立 CLI 附件覆盖 macOS ARM64/x86_64、Linux ARM64/x86_64 和 Windows x64。手动安装 Apple Silicon CLI 时，还需下载本页 `mlx-macos-arm64.metallib`，改名为 `mlx.metallib` 并放在 CLI 同一目录；Unix 可执行文件需赋予执行权限。

## 升级与验证范围

- 从 RC5 升级可直接覆盖安装，保留配置、课程输出及模型缓存。注意：批量任务使用任务内字幕发现，需引擎与桌面同版本——GUI 包内已自带匹配引擎；独立使用旧版 CLI 作为引擎会被桌面端拒绝（`Invalid task JSON`）。
- 本版改动经 macOS 本机回归验证：引擎 155 项、集成 23 项、桌面 232 项测试全部通过；以 149 集 Bilibili 课程实机验收——候选多选（单选/全选/全不选/已有笔记排除与提示）、批量入队两集并完整产出笔记（标题、UP 主、时长、截图、摘要逐项核对）、下载进度与浅色模式均通过；设置页圆圈消失、Ollama/Codex 账号卡片经运行中原生应用验证。
- 已知验证边界：窄窗口下候选区的实机检查未完成（布局沿用既有弹性约束）；批量去重提示未做实机演示（复用既有队列去重逻辑）；Codex 浏览器 PKCE 授权全流程仍未在真实浏览器中点击通过；Windows/Linux 原生视觉、其他硬件识别与长时间高负载使用仍需进一步试用。

启动后在「设置 → 应用」确认版本 `2.0.0-rc.6`；CLI 使用 `--version` 确认。反馈问题时请附系统、版本、复现步骤和已脱敏的诊断信息。

## English

**2.0 RC6** focuses on converting whole courses at once. Multi-part video lists (e.g. Bilibili course playlists) now show real part titles, first-frame previews and durations instead of "video n", and the list became multi-select: check any number of parts and enqueue them in one batch. Batch tasks no longer need per-part pre-reading on the desktop — each task probes the video at runtime and discovers subtitles itself (same Auto semantics as the CLI, falling back to speech recognition when none exist), filling uploader and duration into the note automatically. Downloads show live byte progress with measured speed and ETA plus a determinate bar; AI proofreading and summary stages show live upload/download token counts. The settings page loses a decorative circle artifact and gains an "AI accounts" group surfacing Codex subscription and Ollama local service side by side.

Use the platform assets above or the independent Homebrew `course2md-gui@rc` and `course2md-rc` channels. Stable packages remain unchanged. Verified on macOS (155 engine + 23 integration + 232 desktop tests; live acceptance on a 149-part Bilibili course — multi-select mechanics, noted-part exclusion, a two-part batch producing complete notes, download progress and light mode). Not yet covered: narrow-window inspection of the candidate area, a live duplicate-enqueue message demo, a real-browser PKCE run, and Windows/Linux visuals or sustained-load scenarios.

# v3.0.0-alpha.10：一个视频一个任务，不再卡在「需要确认」，界面缩放滑块

3.0.0 的第十个预览版。任务管理重新整理：每个视频只有一个任务，重试和重新生成都在原任务上进行；之前会让任务停在「需要确认」、后续请求全部等待的问题已去掉。界面缩放改为 75%–200% 的滑块，设置自动生效，可以一次粘贴多个链接批量转换。请先在不重要的视频上试用，遇到问题请[反馈](https://github.com/mizorewww/course2md/issues)。

## 升级前请了解

- **任务列表会被整理并变短**：首次打开时旧任务记录自动转换。同一视频有多条记录时只保留最新一条；已取消且没有笔记的任务被移除；部分完成、需要处理、需要确认的任务都变为「需要处理」。笔记本身不受影响。任务记录不再写入笔记库文件夹，关联已有笔记库不会再带入它的任务。
- **中断的 AI 请求会自动重发**：以前发出后没有确认结果的请求（程序退出、断线、服务 5xx）会让任务停在「需要确认」，等你选择「重新发送」。现在它们在下次运行时直接重发，可能产生额外费用；已完成的回答仍会复用，不重复收费。
- **重跑结果会替换现有笔记**：之前「新结果比已保存的笔记差就保留旧笔记」的保护已去掉。重新生成或重试后，笔记以新结果为准；唯一例外是新摘要失败时保留原来的摘要。
- **替换笔记时留下的旧副本会自动删除**：中断的替换会恢复最新的一份，其余 `old-*` 副本删除，不再提示手动处理。
- 命令行 `--json` / `run-task` 有不兼容变化，见下文。

## 任务：一个视频一个任务

- 任务只有五种状态：等待处理、正在生成笔记、已暂停、需要处理、笔记已生成。不再有「已取消」「部分完成」「需要确认」「正在暂停」。
- 每个笔记库里的每个视频只有一个任务。再次转换、重试和重新生成都更新原来的卡片，不再生成「后续任务」或「重新处理任务」；已在等待或处理中的视频不会重复加入。
- 操作：「继续」恢复暂停的任务；「重试」复用已完成的部分，按钮会写明要补做什么，例如「重试未完成的校对部分」，多个部分未完成时为「补全未完成部分」；「重新生成」丢弃缓存从头开始，会重新发送 AI 请求。另有「全部暂停」「全部继续」「取消任务」「移除任务记录」。
- 取消任务就是移除它，已发布的笔记不会被动到。
- 新增「清空已完成」：只清除任务记录和对应的工作缓存，生成的笔记不会被删除。
- 任务日志使用等宽字体，可以「复制日志」。进度条只在该阶段运行时显示。
- 多个部分因同一原因未完成时只说一次原因，例如「校对未完成、摘要未生成：服务拒绝了 API Key」。

## 界面和设置

- 「文字大小」改为「界面缩放」滑块，75%–200%，每格 5%，拖动时显示实时预览，松开后应用，可「恢复 100%」，也可以用方向键调整。alpha.9 保存的设置继续有效。
- 设置修改后自动生效，去掉了「应用」「应用校对规则」按钮和「更新默认服务」对话框；切换设置分类不再有淡入动画。
- 首次设置时输入的 API Key 在点「继续」后会被保存（以前可能丢失）；服务卡片里新增「检查配置」，计费提示放在旁边。
- 检查 AI 服务时只要求返回有效的非空回答，不再因回答措辞不同误报「样例不一致」。
- 粘贴多个视频链接时可以勾选多个一起转换；其中已有笔记的会先询问是否替换。排队中的视频读取到标题后显示真实标题。
- 阅读页新增「复制笔记」，复制 Markdown 原文。
- 普通在线笔记不再误报缺少离线视频；过长的任务标题最多显示两行。

## 视频和字幕

- 直接读取更多字幕格式：YouTube json3 / srv1–3、TTML、Bilibili bcc、ASS、LRC，修复 yt-dlp 找到字幕但转换失败的情况。
- 系统里安装了比内置更新的 yt-dlp 时优先使用它；deno、node 或 bun 会明确传给 yt-dlp，从 Finder 打开的 macOS 应用也能找到。
- 读不到浏览器 Cookie（例如没有授予「完全磁盘访问权限」）时，公开视频和字幕照常读取；只有 YouTube 确实要求登录时才提示授权。

## 命令行

- `--translate` 和配置中的翻译目标接受任意语言代码或名称（如 `pt`、`Italian`）；简体和繁体中文是不同目标，可以把简体文字稿翻译成繁体。
- 配置文件中有未知的键时不再无法读取。`--gpu-layers` 接受 0–999。
- 云端语音识别失败时显示服务给出的原因（去掉密钥）。
- **`--json` / `run-task` 不兼容变化**：错误代码 `note_kept`、`note_recovery_blocked`、`note_copies_kept` 已移除，`error` 事件不再有 `parts` 和 `path` 字段；新的运行不再产生 `uncertain`。依赖这些的脚本需要更新。

## 从源码构建

- macOS 上 Xcode 的 Metal 工具链版本不匹配时，改用另一种方式编译 Metal 着色器，不再产生 CoreML 识别不可用的构建；检查时实际运行 Metal 编译器。`--app-only` 本地构建使用开发者证书签名，重新构建后保留 macOS 隐私权限。

## 安装

GUI 包含同版本 CLI 引擎，无需另装 CLI。预览版不会替换正式版，AUR 不发布预览版。

- macOS Apple Silicon：`brew upgrade --cask course2md-gui@alpha`，首次安装用 `brew install --cask mizorewww/tap/course2md-gui@alpha`
- 独立 CLI：`brew install mizorewww/tap/course2md-alpha`

引擎和桌面端的单元测试、任务执行和命令行集成测试在 macOS、Windows、Linux 上通过；Windows 安装程序经过安装、原地升级和卸载的自动测试。任务迁移、自动重发和笔记替换用自动测试覆盖，尚未在大量真实旧记录上验证；升级后如发现任务丢失或状态不对，请在任务详情里「复制日志」附在反馈中。

## English

**course2md 3.0.0-alpha.10: one task per video, no more "Needs confirmation" hangs, a UI scale slider.**

**Before you upgrade.**
- The task list is migrated on first launch and gets shorter: only the newest record per video is kept, cancelled tasks without a note are dropped, and partial / needs-attention / needs-confirmation tasks become "Needs attention". Notes are untouched. Task records are no longer stored in library folders.
- AI requests left unconfirmed by a crash, disconnect or 5xx no longer stop the task at "Needs confirmation"; they are sent again on the next run, which may cost money. Finished replies are still reused for free.
- A rerun's result now replaces the saved note even if it finished less; only a failed new summary keeps the old one.
- Leftover `old-*` copies from an interrupted replacement are deleted automatically.
- `--json` / `run-task` has breaking changes (below).

**Tasks.** Five states: Waiting for processing, Generating notes, Paused, Needs attention, Note has been generated. Each video in a library has one task; converting again, retrying and regenerating update that card instead of adding follow-up tasks. Continue, Retry (named for what it finishes, e.g. "Retry unfinished proofreading"), Regenerate (from scratch, resends AI requests), Pause all / Resume all, Cancel task (removes it; published notes are never touched), Remove task record, and Clear completed (records and work caches only, never notes). The task log is monospace with Copy log; progress bars show only for the running stage. A cause shared by several unfinished parts is stated once.

**Interface and settings.** A UI scale slider (75–200 % in 5 % steps) with a live preview, applied on release, arrow-key steps and Reset to 100 %. Settings apply automatically (no Apply buttons). Onboarding keeps the typed API key; service cards gain Check configuration; service checks accept any valid non-empty reply. Pasting several links lets you convert several videos at once, asking before replacing existing notes. The reader gains Copy note. Online notes no longer report a missing offline video.

**Videos and subtitles.** json3 / srv1–3, TTML, Bilibili bcc, ASS and LRC subtitles are read directly; a newer installed yt-dlp is preferred; deno/node/bun are passed to yt-dlp; public videos work when browser cookies can't be read, and Full Disk Access is asked for only when YouTube requires sign-in.

**CLI.** `--translate` accepts any language code or name, with zh-Hans and zh-Hant as separate targets; unknown config keys are ignored; `--gpu-layers` takes 0–999; cloud speech errors show the service's reason. **Breaking for `--json` / `run-task`:** error codes `note_kept`, `note_recovery_blocked` and `note_copies_kept` and the `error` event's `parts` and `path` fields are removed; new runs no longer report `uncertain`.

**Install or upgrade:**
- `brew upgrade --cask course2md-gui@alpha`, or `brew install --cask mizorewww/tap/course2md-gui@alpha` for a first install.
- `brew install mizorewww/tap/course2md-alpha` for the standalone CLI.
- Or use the downloads in the table above; Windows has an installer.

Prereleases don't replace the stable release, and AUR skips them.

**Testing so far:** unit, task-execution and CLI tests pass on macOS, Windows and Linux, and the Windows installer passes its install/upgrade/uninstall smoke test. Task migration, automatic resending and note replacement are covered by automated tests but not yet by many real old records. If tasks go missing or look wrong after upgrading, please attach the task's log (Copy log in its details).

Please report any issues.

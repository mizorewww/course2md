# v3.0.0-alpha.9：Windows 返回按钮，AI 校对少失败，ETA 更稳

3.0.0 的第九个预览版。修复 Windows 上笔记页返回按钮点不动的问题；AI 校对更少出现「1/165 失败」这类部分失败，失败时说清楚是哪一段、为什么；AI 处理按批显示剩余时间，关键帧检测等阶段的剩余时间不再跳动。请先在不重要的视频上试用，遇到问题请[反馈](https://github.com/mizorewww/course2md/issues)。

## Windows 返回按钮（#72）

- 在 Windows 上，笔记页标题栏里的「返回」「搜索」「⋮」按下后只显示按下状态、没有反应，打开的笔记无法用返回按钮离开。原因是整条标题栏都是窗口的拖动区域，这几个按钮包在提示（tooltip）里，按下被系统当成拖动窗口的开始，松开被吞掉。macOS 不受影响。
- 界面组件库更新到 gpui-kit-material 0.1.4：标题栏里的按钮区域不再算作拖动区域，按钮正常响应，空白处仍可拖动窗口和双击最大化。已在真实 Windows 环境中用真实鼠标点击验证。

## AI 校对（#71）

- **少失败**：
  - 模型漏掉、合并或重新编号段落时，只保留确实对应原段落的结果，其余段落单独再问，不再整批反复失败，也不会把文字错放到别的段落。翻译遇到这种回答会整批重问。
  - 服务因内容拒绝处理某一批时，逐步拆小，找到被拒绝的那一段，其余段落照常完成；拆分有次数上限，不会无限产生请求。
  - 遇到限流或网关繁忙时，等待时间从 4 秒开始加倍到 60 秒，限流最多重试 6 次；只是暂时失败的批次在最后再试一次。
- **失败时说清楚**：仍然失败的段落保留原文，笔记标记为部分完成。任务卡片、任务详情和阅读页都会显示哪一段（时间范围）、服务给出的原因，例如「37 段中有 1 段保留原文；首个错误：11:33–12:05：服务拒绝处理这部分内容：Content Exists Risk」，旁边是「重试未完成的校对部分」，只重新发送没完成的部分。重试仍未完成时保持这个说明，不再变成「需要处理」和一段原始错误。
- **从 alpha.8 升级**：alpha.8 里补做后卡在「需要处理」的任务，打开后会恢复为部分完成并可以重试，已完成的批次不会重新发送。
- **错误详情**：AI 服务返回的错误说明会（去掉密钥等敏感内容后）保存在笔记库的 `.course2md/work/<任务>/requests/` 中，便于反馈问题。
- 命令行 `--json` 只新增字段（如进度单位 `batches`、`first_failure`）。重试没有完成更多内容时，现在以部分完成（`partial: true`）结束，和其他部分完成一样退出码为 0。

## 剩余时间

- AI 校对、翻译和摘要按批显示进度和剩余时间，例如「3 / 12 批 · 预计剩余 45 秒」。重试时从已保存结果读回的批次不计入速度。
- 所有阶段（包括关键帧检测、下载、语音识别）使用同一种剩余时间估算：开始几秒后才显示，每秒最多更新一次，只有明显变化才调整，向上调整更谨慎，并按 5 秒、10 秒、30 秒、1 分钟等取整，不再忽上忽下。处理很慢的模型也能显示剩余时间。

## English

**course2md 3.0.0-alpha.9: the Windows back button, fewer AI proofreading failures, steadier ETAs.**

**Windows back button (#72).** On Windows the note page's Back, Search and ⋮ buttons showed pressed and did nothing, so an open note couldn't be left with Back. The whole title bar is a window drag area, and these tooltip-wrapped buttons' presses were taken as the start of a window drag, which swallowed the release. macOS was unaffected. gpui-kit-material 0.1.4 keeps title-bar controls out of the drag area; empty bar space still drags and double-click maximizes. Verified with real mouse input on a Windows machine.

**AI proofreading (#71).**
- An answer that drops, merges or renumbers paragraphs keeps only text that really belongs to its paragraph and asks for the rest again, instead of failing the whole batch every retry or misplacing text. A translation with gaps is asked again whole.
- A batch the service refuses for its content is split down to the refused paragraph, within a request budget.
- Rate limits and busy gateways wait 4 s doubling to 60 s (up to 6 tries for rate limits); transient failures get one more try at the end.
- A paragraph that still fails keeps its original text; the task card, details and reader say which part (time range) and why (the service's words), with "Retry unfinished proofreading", which sends only that part. A retry that finishes nothing more stays this partial result instead of an error.
- Tasks stuck in "Needs attention" after an alpha.8 retry open as partial and can be retried without resending finished batches.
- The AI service's error text (keys and credentials removed) is kept under `<library>/.course2md/work/<task>/requests/` for bug reports.
- `--json` only gains fields (unit `batches`, `first_failure`). A retry that finishes nothing more now ends with `partial: true` and exit code 0, like other partial results.

**ETA.** AI proofreading, translation and summaries show "3 / 12 batches · 45s remaining". Every stage, keyframe detection included, uses one smoothed estimate: shown after a few seconds, updated at most once a second, changed only on a clear difference (more reluctantly upward), rounded to steps. Slow models get an ETA too; replayed batches don't count as speed.

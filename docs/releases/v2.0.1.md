# v2.0.1：Windows 窗口按钮、可用的 Intel NPU 与内置工具

2.0.1 是 2.0 的修复版，主要修复 Windows：窗口终于有了最小化、最大化和关闭按钮，Intel NPU 识别可以正常使用，路径和文件名也不再出错。桌面安装包现在内置 ffmpeg 等处理工具，下载后即可使用。

## Windows

- **窗口按钮和顶栏**：2.0.0 在 Windows 上没有最小化、最大化和关闭按钮。现在按钮画在顶栏右侧，样式与 Windows 11 一致，支持贴靠布局；拖动顶栏可移动窗口，双击可最大化或还原，打开对话框时也能使用。Linux 使用客户端装饰（如 Wayland 下的 GNOME）时同样补上了这些按钮。
- **首次打开的窗口不再超出屏幕**：窗口按屏幕可用区域（不含任务栏）缩放并居中。2.0.0 在小屏幕上窗口会超出屏幕顶端，无法拖动或关闭。
- **路径和文件名**：设置和存储页面不再显示 `\\?\C:\…` 形式的路径，「打开位置」可以正常打开；标题为 `CON`、`NUL` 等设备名或以句点结尾的视频也能正确保存；笔记中的本地视频路径正确显示。

## Intel NPU 识别

- **NPU 识别可以正常使用了**：2.0.0 的 NPU 默认模型 Qwen3-ASR 无法加载，NPU 任务总会失败；Windows 上也检测不到 NPU。现在 NPU 默认使用 Whisper large-v3-turbo（INT8），Windows 和 Linux 都能识别 Intel NPU。
- **自动迁移**：之前在 NPU 上选择了 Qwen3 的设置会自动改为 Whisper large-v3-turbo，并在识别设置中提示一次；CLI 每次运行提示一次，不改写 `config.toml`。
- 首次使用时下载组件和约 1 GB 模型不再因超时而失败；停止任务时会结束全部子进程；中文 Windows 上的工作进程输出不再导致启动失败。

## 内置工具

- **桌面安装包内置 ffmpeg/ffprobe**（LGPL，从源码构建，支持 https），无需另行安装。应用优先使用自带的工具，找不到时才使用系统 PATH 中的版本。
- **Windows 和 Linux 安装包内置 uv 和 llama-server**（Vulkan 版，支持 NVIDIA、AMD、Intel 显卡，没有显卡时使用 CPU），本地识别和 NPU 识别不再需要另装 llama.cpp 或 Python。
- **yt-dlp 改用 onedir 版本**：每次调用从 8–10 秒缩短到通常不到 1 秒，在线视频的预览明显变快。2.0.0 中 yt-dlp 自检只等 3 秒，内置的 yt-dlp 有时会被误报为缺失，现已修复。
- **Windows 检查 Visual C++ 运行库**：内置的 llama-server（本地 GPU/CPU 识别）需要它。缺少运行库时，引导和设置会说明原因，并提供 Microsoft 安装程序的下载按钮和重新检查。
- `course2md doctor` 显示 ffmpeg、ffprobe、yt-dlp、aria2c 和 llama-server 实际使用的路径，以及它们是应用自带还是系统安装的。
- Homebrew cask 不再依赖 Homebrew 的 ffmpeg（应用已自带）；仍会安装 yt-dlp 和 aria2。

## 安装

GUI 包含同版本 CLI 引擎，无需另装 CLI；独立 CLI 不会安装桌面应用。

**包管理器：**

- macOS Apple Silicon：`brew install --cask mizorewww/tap/course2md-gui`（会一并安装 yt-dlp 和 aria2）
- Arch Linux / CachyOS x86_64：`yay -S course2md-gui-bin`（使用系统的 ffmpeg、yt-dlp 和 aria2；本地 GPU/CPU 识别需另装可选依赖 `llama-cpp`，Intel NPU 识别需另装 `uv`）
- 独立 CLI：`brew install mizorewww/tap/course2md` 或 `yay -S course2md-bin`

**手动下载桌面应用：**

| 平台 | 安装包 | 使用方式 |
| --- | --- | --- |
| macOS Apple Silicon，macOS 15+ | [DMG](https://github.com/mizorewww/course2md/releases/download/v2.0.1/course2md-gui-macos-arm64.dmg) | 退出旧应用，将完整 `course2md.app` 放入「应用程序」 |
| Windows x64 | [桌面 ZIP](https://github.com/mizorewww/course2md/releases/download/v2.0.1/course2md-desktop-windows-AMD64.zip) | 完整解压，打开 `course2md-desktop.exe`，保留同目录的其他文件 |
| Linux x64 | [桌面 tar.gz](https://github.com/mizorewww/course2md/releases/download/v2.0.1/course2md-desktop-linux-x86_64.tar.gz) | 完整解压，运行 `./course2md-desktop`；预编译包基于 Ubuntu 24.04 |

桌面安装包已内置 ffmpeg、ffprobe 和 yt-dlp；Windows 和 Linux 包另含 uv 和 llama-server，Windows 包还含 aria2。独立 CLI 仍需自行安装 ffmpeg 和 yt-dlp，请参阅 [安装指南](https://github.com/mizorewww/course2md/wiki)。

**独立 CLI**：macOS / Linux 可运行

```sh
curl -fsSL https://raw.githubusercontent.com/mizorewww/course2md/v2.0.1/install.sh | bash
```

也可下载本页的独立可执行文件，用法与 [2.0.0](https://github.com/mizorewww/course2md/releases/tag/v2.0.0) 相同。

## 升级

Homebrew 运行 `brew update && brew upgrade --cask course2md-gui`（CLI 为 `brew upgrade course2md`），AUR 照常更新；手动安装时退出旧应用，替换整个应用或解压目录。设置、笔记和模型缓存都会保留。从 1.7 或 RC 升级请参阅 [2.0.0 发布说明](https://github.com/mizorewww/course2md/releases/tag/v2.0.0)。

启动后在「设置 → 应用」确认版本 `2.0.1`；CLI 使用 `course2md --version` 确认。

## 验证范围

Windows 窗口按钮、拖动、双击和对话框上的操作已在 GitHub 的 Windows 机器上用真实鼠标输入验证；发布前的试运行已用正式证书完成内置工具的 macOS 签名和公证。Linux 客户端装饰下的窗口按钮只经过自动测试；Intel NPU 和 Visual C++ 运行库检查尚未在真实设备上验证。如遇问题请[反馈](https://github.com/mizorewww/course2md/issues)。

## English

**course2md 2.0.1** fixes Windows. The window now has minimize, maximize and close buttons, drawn after Windows 11's with snap layouts. Dragging the title bar moves the window, double-clicking maximizes or restores it, and both work over an open dialog. Linux with client-side decorations (GNOME on Wayland) gets the buttons too. The first window fits the screen's usable area instead of opening past its top edge. Paths no longer show the `\\?\` prefix and Open location works. Videos titled with device names such as `CON`, or ending in a dot, save correctly.

**Intel NPU recognition works.** 2.0.0's NPU default, Qwen3-ASR, could not load, and Windows never detected the NPU. The NPU now defaults to Whisper large-v3-turbo (INT8) and is detected on Windows and Linux. Saved Qwen3 choices for the NPU switch to it: the app says so once in the recognition settings, and the CLI prints a notice on each run without rewriting `config.toml`. The first download no longer times out. Stopping a task ends the whole worker process tree, and worker output on Chinese Windows no longer breaks startup.

**Bundled tools.** Desktop packages bundle ffmpeg and ffprobe: LGPL, built from source, with https. The app uses its own tools before PATH. Windows and Linux packages also bundle uv and a Vulkan llama-server, so local and NPU recognition need no separate llama.cpp or Python. yt-dlp is now the onedir build: each call usually takes under a second instead of 8–10 s, and it is no longer wrongly reported missing. On Windows, the app checks for the Visual C++ runtime that the bundled llama-server (GPU/CPU recognition) needs, and links to Microsoft's installer. `course2md doctor` shows where each tool runs from, bundled or system. The Homebrew cask no longer depends on Homebrew's ffmpeg; it still installs yt-dlp and aria2.

**Install:** `brew install --cask mizorewww/tap/course2md-gui` (Apple Silicon) or `yay -S course2md-gui-bin` (Arch x64), or use the platform downloads above. Desktop downloads bundle ffmpeg, ffprobe and yt-dlp; the Windows and Linux ones add uv and llama-server, and Windows also aria2. The AUR package uses Arch's ffmpeg, yt-dlp and aria2; local GPU/CPU recognition there needs the optional `llama-cpp` package, and Intel NPU recognition needs `uv`. The standalone CLI still needs ffmpeg and yt-dlp installed. **Upgrade** with `brew upgrade --cask course2md-gui` or by replacing the app; settings, notes and models are kept. Confirm version `2.0.1` in Settings → Application.

The Windows caption buttons, drag, double-click and dialog behavior were checked with real mouse input on a GitHub Windows machine. A release dry run signed and notarized the macOS app with its bundled tools. The Linux client-side buttons were tested automatically only; Intel NPU and the Visual C++ runtime check have not been tested on real hardware. Please report any issues.
